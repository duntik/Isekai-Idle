# Бесплатная синхронизация для GitHub Pages

Игра остаётся статическим сайтом. GitHub Pages отдаёт файлы, а Supabase хранит одну облачную копию на аккаунт. Локальная игра не требует сервиса или входа.

## Однократная настройка владельцем

1. Создайте аккаунт и проект на https://supabase.com/dashboard . Выберите Free, придумайте пароль базы (он не нужен игре), дождитесь запуска проекта.
2. В SQL Editor выполните содержимое `supabase.sql`. Это таблица, политики доступа только к собственному сохранению и две функции чтения/записи с проверкой версии.
3. В настройках проекта найдите Project URL и **publishable key** (или legacy **anon key**). В `cloud-config.js` укажите URL без завершающего `/` и публичный ключ. Например: `{ url: 'https://your-project.supabase.co', key: 'sb_publishable_...' }`.
4. **Никогда не помещайте secret/service_role key, пароль базы или пароль аккаунта в репозиторий.** Публичный ключ допустим в браузере; доступ к данным ограничивает RLS и пользовательская авторизация.
5. В Authentication → URL Configuration укажите Site URL `https://duntik.github.io/Isekai-Idle/`, добавьте его в Redirect URLs. Включите Email provider и подтверждение почты. Для общедоступной регистрации настройте собственный SMTP: встроенная отправка Supabase ограничена и подходит для тестирования, а не публичного потока игроков. Альтернатива для личного использования — создать свой тестовый аккаунт через Auth dashboard и входить им на устройствах.
6. Закоммитьте только `cloud-config.js` с публичными значениями. GitHub Pages подхватит изменения при публикации ветки main.

## Использование

Откройте «Данные и облако». Зарегистрируйтесь, подтвердите почту и войдите. На первом устройстве нажмите отправку. На втором войдите тем же аккаунтом и загрузите облачную копию. Вход сам не заменяет прогресс.

После согласования можно включить отправку каждые пять минут. Сессия и пароль не сохраняются на диск; после перезагрузки страницы войдите снова. Автоотправка по умолчанию выключена. При отсутствии сети локальная игра продолжает работать; отправка повторится при следующем интервале. Обновление вкладки/закрытие страницы не гарантирует последнюю облачную отправку — для перехода на другое устройство сначала отправьте вручную.

Облачные версии записываются атомарно: если другая вкладка или устройство уже изменили облако, устаревшая отправка отклоняется. Автоотправка отключается, игрок выбирает загрузку либо подтверждённую замену. Прогресс двух устройств не складывается: это две расходящиеся ветки одной игры.

До замены локального прогресса сохраняется резервная копия. Есть до восьми локальных копий, код с gzip-сжатием (если поддерживается браузером) и проверкой повреждения, файлы JSON с датой. Поддерживается импорт старых файлов v2 без оболочки. История резервных копий, пароль и облачная сессия не включаются в код.

## Ограничения и проверка

Free имеет квоты; неактивные проекты могут приостановить после семи дней низкой активности. Восстановление выполняется через dashboard. Бесплатность не означает неограниченный сервис. Проверяйте текущие условия: https://supabase.com/pricing и https://supabase.com/docs/guides/platform/free-project-pausing .

После настройки проверьте настоящие запросы: вход двух разных аккаунтов (каждый видит только свои данные), отправку с двух устройств (второе получает конфликт), загрузку с офлайн-начислением, выход, неверный пароль, отключённую сеть. Эти проверки требуют вашего настроенного проекта; локальные тесты API используют имитацию сервера и не заменяют проверку RLS в Supabase.

Документация: https://supabase.com/docs/guides/auth , https://supabase.com/docs/guides/database/postgres/row-level-security , https://supabase.com/docs/guides/auth/auth-smtp .
